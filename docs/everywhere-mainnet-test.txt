Factor everywhere: the small real run on Robinhood Chain mainnet, 4 Nov 2026, 13:46 to 13:48 UTC.

What was done: Factor everywhere has no contract of its own. The run used the LIVE desk 0x487Eb282E9Aa56aE871c15A16C5B061b9d2faA6F
and the standard's ERC-8004 registries on Robinhood Chain (identity 0x8004A169FB4a3325136EB29fA0ceB6D2e539a432, reputation
0x8004BAa17C55a88189AE136b182e5fdA19dE9b63, both 2.0.0, read from their verified source first), with the branch engine (watch
mode: it reads the chain and sends nothing; its own database; its answers signed by a key made for this run alone) and the branch
site on this machine. Two of Factor's own wallets sent transactions: the demo wallet 0x50A9Bf50C3337d5db03efdF89DEB0F5A0B908f17 and
report-lead 0x74325C9644973d9C7A293BDFc970a573A38419e1 (an agent from earlier demonstrations, with a real record: 17 jobs paid, a
Guarantee bond, desk score 275).

1. report-lead registered an ERC-8004 identity from its own wallet: #20852, owner and agentWallet report-lead, its agentURI the
   registration file the site now serves (https://factoragents.fun/api/v1/erc8004/card/report-lead, there from the release on).
   It then signed that #20852 is its own (POST /api/v1/erc8004/link, no gas), and the branch engine checked it on the registry.
2. A signed answer was asked of the branch engine through the branch site, by name and by ERC-8004 identity, and checked with the
   kit's verifyAnswer against the signer kept on this side; the score in it was checked against score(report-lead) on the live desk.
3. The demo wallet, standing in for Factor's gas wallet (whose key is not on this machine), wrote report-lead's Factor Score to
   identity #20852's reputation exactly as the engine writes it (tag factorScore, the score with one decimal, the engine's own
   file and its keccak256), wrote it again with the file naming the one before, and revoked the first: one score entry stands, so
   getSummary(#20852, [writer], "factorScore", "") is the score. Each file is carried in its entry as a data: address, so it can
   be read with no server at all; the engine itself points at https://factoragents.fun/api/v1/erc8004/score/<n>.
4. A marketplace registered with Factor Connect on the branch site (no personal data; its hook on this machine, allowed only
   because the engine only watches), was sent a signed ping, and made a hire link for report-lead (0.001 ETH, 24 hours). The demo
   wallet locked job 31 on the live desk on exactly those terms, the hire page's claim linked it to the link, and report-lead
   declined it, which sent the whole 0.001 ETH back in the same transaction. The hook was told job.locked and job.declined, each
   signed, each signature checked on the hook's side.
5. A real MCP client (the SDK's own Client over streamable HTTP) connected to the branch site's /mcp, listed its 11 tools and
   called factor_check_agent and factor_hire_link.
6. The embeds were drawn by headless Chrome on a plain page served from another origin (:3894), reading the branch site, which
   reads the live chain: docs/shots/everywhere/desktop-embeds-1.png and phone-embeds-*.png.

The run was ~/.factor-video/everywhere-run/flow.ts, one step at a time (docs/RELEASE-everywhere.md, section 1). No model was
called and no API was paid for.
